# 2026-11-15 Agent 优化记录

对照版本为 `c0094c6`。沿用 12 道文档题、6 道流程题、原评分规则、`deepseek-flash`、同版本 BGE 和本机虚构 MySQL 台账。两个版本都实际调用 DeepSeek。样例量有限，每次模型生成可能变化。

## 实现

| 问题 | 改动 | 验证 |
| --- | --- | --- |
| 只回答了复合问题的一部分，整题仍被标为直接支持 | 单轮任务在规划时列出待核对事项。复核分别生成子问题的结论、引用和状态，程序检查应有项数与引用 ID，缺项时降级总状态。对缺证项有一次定向补查，Markdown 保留已核实的部分。 | 单测覆盖错误支持状态、无效引用和定向补查。独立虚构条款只给出 45 分钟时限时，验收分别核对「工单分级」和「响应时限」。 |
| 重复核对步骤可以通过原来的依赖校验，阻止补证任务结束 | 每步用一段来自用户需求的目标原文定位，按归一化的目标合并重复步骤，重映射依赖并校验有向无环图，然后由 LangGraph 持久化计划。 | 单测给出复述步骤及指向它的依赖，检查合并后保留真正的任务和依赖。R01 使用真实 MySQL 检查点，新 Python 进程补交附件。 |
| 单行命中遗漏上文定义 | 混合检索保留原有命中，额外带入最多两条相邻原文。邻接只在同一文件和内容版本内成立，复用原行号与证据 ID。 | 使用旧版实跑生成的检索词、相同问题及文档，对 10 道有预期原文行的题只重跑两版检索函数。完整原文召回 **9/10 → 10/10**。D12 新召回第 2 行，同第 3 行一起支撑定义和时限。 |

## 复跑

在仓库根目录运行，环境及样例配置见 [Agent 评测](README.md)。用同样的命令在 `c0094c6` 工作区取得旧版对照。复跑 R01 时可用不同的 `--output` 路径保留各次结果。

```powershell
& '.\.venv\Scripts\python.exe' -X utf8 -m unittest discover -s tests -v
& '.\.venv\Scripts\python.exe' -X utf8 -m evaluation.run --suite documents
& '.\.venv\Scripts\python.exe' -X utf8 -m evaluation.run --suite workflows
& '.\.venv\Scripts\python.exe' -X utf8 -m evaluation.run --suite workflows --case R01
```

独立缺证探针的问题是「合同将什么情形定义为最高优先级？记录该级别的工单后多久要响应？」。两条虚构条款分别为「最高优先级的工单登记后须在 45 分钟内响应。」与「普通工单在一个工作日内响应。」。用 DeepSeek 混合检索运行，预期保留 45 分钟和引用，总状态为证据不足。

## 简历表述

- 基于 Python、LangGraph 和 MySQL 构建文档分析 Agent，设计子问题级证据复核与缺证定向补查，在 Markdown 报告中保留有据结论和未覆盖事项。
- 实现 Plan 目标定位、重复步骤合并和依赖重映射，使用 MySQL 检查点保存计划及已复核结果。虚构合同补证场景连续三次跨进程验收通过。
- 优化关键词与 BGE 混合检索，按文档版本补充相邻原文并保留行号引用。自建 18 道题评测，在固定检索词的 10 道有标准证据题中，完整证据召回由 9/10 提升至 10/10。

面试时可用 D12 解释检索与复核的分工。原文第 2 行定义故障范围，第 3 行规定响应时限。邻行扩展找回定义，逐项复核确认两项各自有引用。另一道只有时限的独立探针验证材料确有缺口时如何报告。
